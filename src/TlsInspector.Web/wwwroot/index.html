Pick an endpoint to inspect

Every TLS client answers the same four questions before it sends a single byte of application data. The inspector runs two handshakes against your target: one with validation suspended, so even a broken certificate can be read, and one with validation untouched, so the verdict you see is the one a real client reaches.

  1. Does the chain lead somewhere trusted? Each certificate is signed by the one above it, ending at a root the client already trusts.
  2. Is it valid right now? Expiry bounds how long a stolen key stays useful and keeps revocation data meaningful.
  3. Does it cover this hostname? Without binding the certificate to the name you asked for, any trusted certificate could impersonate any site.
  4. Is the cryptography still strong enough? Key sizes, signature algorithms and protocol versions all age out of acceptance.
